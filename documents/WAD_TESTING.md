# WAD_TESTING.md — ручная регрессия SLADE Mobile

Документ описывает текущий подход к ручной проверке WAD в SLADE 3 MOBILE и официальный набор тестовых fixture-файлов.

## Текущий подход

Автоматизированные native tests и отдельный native test runner в проекте не используются.

На текущем этапе regression testing выполняется вручную через обычный Android UI на фиксированном наборе WAD-fixture файлов.

Это сознательное упрощение: сначала проверяется реальное поведение приложения на конкретных входных данных, а автоматизация может быть возвращена позже, если появится стабильная test infrastructure.

### Бинарная структура fixtures

Для валидных файлов проверяются:

- `magic` — IWAD/PWAD;
- `numlumps`;
- `infotableofs`;
- границы directory;
- offset и size каждого lump;
- попадание данных и directory в пределы файла;
- корректность 16-байтовых directory entries.

Текущая структурная проверка дала следующий результат:

- **9/10** fixtures — внутренне согласованные WAD;
- **1/10** — намеренно malformed fixture;
- `07_corrupt_directory.wad` содержит directory offset `999999`, выходящий далеко за пределы файла;
- `08_large_and_many.wad` содержит 81 lump и имеет размер около 2 MiB;
- `09_iwad_marker.wad` использует настоящий `IWAD` magic;
- `03_minimal_map.wad` содержит 11 ожидаемых map-lump имён, начиная с `MAP01`.

Проверка бинарной структуры подтверждает корректность fixture-файлов как входных данных; она не заменяет ручную проверку поведения самого приложения.

## Категории fixture-файлов

### Минимальные WAD

Проверяют:

- распознавание IWAD/PWAD;
- корректное открытие пустого архива;
- нулевое количество lumps;
- работу с минимальным количеством данных.

### Структурные и функциональные WAD

Проверяют:

- один и несколько lumps;
- разные размеры данных;
- большой lump;
- большое количество entries;
- дубликаты имён;
- пустые и 8-символьные имена;
- MAP01;
- PLAYPAL;
- picture-данные;
- IWAD marker;
- минимальный сценарий сохранения.

### Повреждённые WAD

`07_corrupt_directory.wad` содержит заведомо недопустимый directory offset.

Главное требование: приложение должно корректно сообщить об ошибке и не завершиться аварийно.

При обнаружении других malformed cases их следует добавлять отдельными fixture-файлами, не изменяя существующий набор.

## Ручной regression workflow

Для каждого fixture:

1. Открыть WAD через Android SAF.
2. Проверить успешное открытие либо ожидаемую ошибку.
3. Проверить количество и имена entries.
4. Проверить чтение содержимого там, где это применимо.
5. Проверить preview поддерживаемых типов.
6. Для редактируемых WAD проверить Rename/Delete/Move/Add/Replace.
7. Проверить Save As.
8. Закрыть и повторно открыть сохранённый WAD.
9. При необходимости проверить Discard.
10. Зафиксировать фактический результат отдельно от ожидаемого.

### Рекомендуемые сценарии по fixtures

- **01_empty.wad** — открыть и проверить пустой список entries.
- **02_basic.wad** — открыть, проверить разные entries и размеры, выполнить базовые операции редактирования.
- **03_minimal_map.wad** — открыть и проверить все map lumps.
- **04_palette.wad** — открыть PLAYPAL и проверить чтение/preview, если поддерживается текущим UI.
- **05_picture.wad** — открыть picture entry и проверить preview.
- **06_duplicate_names.wad** — проверить отображение, выбор и операции с одинаковыми именами.
- **07_corrupt_directory.wad** — проверить отказ при открытии без crash.
- **08_large_and_many.wad** — открыть большой архив, проверить список из большого количества entries и чтение большого lump.
- **09_iwad_marker.wad** — проверить открытие IWAD и корректное отображение его entries.
- **10_tiny_savetest.wad** — выполнить минимальное изменение, Save As, закрыть, повторно открыть и проверить результат.

## Правило для fixture-файлов

Fixture должен оставаться неизменным исходным входом для повторной проверки.

Изменения, выполняемые приложением во время теста, должны сохраняться в отдельный выходной файл, а не поверх оригинального fixture.

Архив с эталонными fixtures должен распространяться отдельно от исходного кода проекта. Ссылка выше указывает на текущий архив набора.

## Связь с архитектурой

Ручные проверки проходят через тот же путь, который используется приложением:

```
Android UI
    ↓
SladeNative
    ↓
JNI
    ↓
ArchiveSession / native archive layer
    ↓
SLADE core
```

Поэтому fixture-тестирование одновременно проверяет не только парсер WAD, но и интеграцию native слоя с Android UI.
