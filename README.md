# SLADE 3 MOBILE

SLADE 3 MOBILE — это портирование/интеграция редактора [SLADE](https://github.com/sirjuddington/SLADE) для Android, направленное на редактирование WAD-файлов и связанные с ними рабочие процессы для ресурсов на движке Doom на устройствах Android.

Проект разрабатывается непосредственно на Android, с использованием Android Code Studio в качестве основной среды разработки. Цель — сделать практический функционал SLADE доступным без необходимости использования настольного ПК.

> **Статус проекта:** WAD Editor MVP завершён; текущий этап — структурный рефакторинг  
> **Текущая базовая версия:** `v0.1.0`

## Возможности

Текущий MVP включает:

- открытие и просмотр WAD-архивов;
- список записей WAD;
- предварительный просмотр поддерживаемых типов ресурсов;
- переименование записей;
- удаление записей;
- перемещение записей;
- добавление записей;
- замена содержимого записей;
- экспорт записей;
- отслеживание состояния изменённости;
- Save As через Android Storage Access Framework (SAF);
- сохранение в исходный файл после предварительной валидации;
- отмену несохранённых изменений через Discard Changes;
- нативную интеграцию на C++ с кодовой базой SLADE;
- Android-специфичный слой совместимости.

Текущий нативный путь редактирования ориентирован на **WAD**. Поддержка PK3/ZIP в текущем формате не завершена и остаётся задачей будущих этапов.

### Важное уточнение по сохранению

Save As создаёт новый файл через SAF. Сохранение в исходный файл выполняется по схеме `validate → commit`: архив сначала сериализуется и проверяется в памяти, после чего проверенные байты записываются в исходный документ, открытый через SAF в режиме `rwt`.

Этот путь **не является атомарной заменой файла**. Если запись исходного документа будет прервана после открытия его в режиме `rwt`, исходный файл может оказаться обрезанным или частично записанным. Поэтому ограничение SAF и отсутствие атомарного replace явно считаются частью текущей архитектуры.

## Зачем нужен этот проект

SLADE — мощный редактор ресурсов для игр на движке Doom и связанных с ним игр, но его традиционный рабочий процесс на ПК предполагает наличие настольного компьютера.

SLADE 3 MOBILE существует, чтобы исследовать возможности переноса этого рабочего процесса на Android.

Проект не ставит целью немедленно заменить настольную версию. Вместо этого он стремится предоставить полезный мобильный редактор, постепенно выстраивая поддерживаемую нативную архитектуру для Android вокруг кодовой базы SLADE.

## Архитектура

### Текущая архитектура

Фактическая реализация на текущем этапе выглядит так:

```text
Android UI / MainActivity
        │
        ▼
SladeNative.kt
        │
        ▼
JNI / native-lib.cpp
        │
        ▼
ArchiveSession
        │
        ▼
WadArchive / SLADE headless core
```

`ArchiveSession` уже существует, но сейчас является WAD-ориентированной нативной сессией. Kotlin-вызовы проходят через один выделенный background-поток, чтобы не допускать конкурентного доступа к изменяемому native-состоянию.

### Целевая архитектура

Структурный рефакторинг постепенно ведёт к следующему разделению:

```text
Android UI
    │
    ▼
ViewModel / UI State
    │
    ▼
Archive Repository / application layer
    │
    ▼
SladeNative / JNI
    │
    ▼
Native Archive Layer
    ├── ArchiveSession
    ├── ArchiveOperations
    ├── EntryData
    └── Save Pipeline
    │
    ▼
SLADE Core
```

`ViewModel`, `Repository` и отдельные `ArchiveOperations` являются **целевой архитектурой**, а не утверждением, что такие компоненты уже существуют в текущем коде.

## Технологический стек

- **Платформа:** Android
- **Минимальный Android API:** 24
- **Целевой Android API:** 34
- **Compile SDK:** 36
- **ABI:** `arm64-v8a`
- **Язык:** Kotlin + C++20
- **Нативная сборка:** CMake
- **Система сборки:** Gradle / Android Gradle Plugin
- **Нативный код:** выбранные headless-компоненты SLADE + Android compatibility layer
- **Хранилище:** Android Storage Access Framework (SAF)

Основная среда разработки — **Android Code Studio**. Точные версии SDK/NDK/CMake и остальных инструментов указаны в [`documents/TECHNICAL.md`](documents/TECHNICAL.md).

## Установка

1. Откройте страницу Releases.
2. Скачайте последний файл `app-debug.arm64-v8a.apk`.
3. Установите APK на Android-устройство с поддержкой ARM64 (`arm64-v8a`).
4. Запустите SLADE 3 Mobile.

### Требования

- Android-устройство с архитектурой ARM64 (`arm64-v8a`).
- Android API 24 или новее.

Текущая версия является debug-сборкой и предназначена для тестирования. Перед редактированием рекомендуется создавать резервные копии важных WAD-файлов.

## Процесс разработки

Git используется для сохранения возможности восстановления проекта в процессе рефакторинга.

Стабильная базовая версия:

```text
master
└── v0.1.0
    └── WAD Editor MVP
```

Правило проекта: новые изменения выполняются в отдельных feature/refactoring-ветках, а не непосредственно в стабильной базовой ветке.

Пример:

```bash
git switch -c refactor/architecture
```

Предпочтение отдаётся небольшим, сфокусированным коммитам, чтобы отдельные изменения можно было проверять, тестировать и откатывать независимо друг от друга.

## Философия проекта

1. **Android прежде всего** — разработка должна оставаться возможной без настольного ПК.
2. **Сохранение работающей функциональности** — рефакторинг не должен без необходимости ломать существующий MVP.
3. **Использование ядра SLADE** — зрелую функциональность не следует переписывать без веской причины.
4. **Чёткие границы** — UI Android, состояние приложения, JNI и логика работы с нативными архивами должны иметь определённые зоны ответственности.
5. **Тестирование перед расширением** — структурные изменения должны быть проверены перед добавлением крупных новых функций.
6. **Небольшие коммиты в Git** — каждое значимое изменение должно оставаться легко проверяемым и откатываемым.
7. **Планирование роста** — архитектура должна в конечном итоге поддерживать больше форматов архивов и редакторов ресурсов, не превращая слой Android в монолит.

SLADE и связанный с ним исходный код остаются предметом соответствующих авторских прав и лицензий.
